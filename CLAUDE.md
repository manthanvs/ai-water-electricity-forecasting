## 4. Hard invariants (never break these)

1. No fabricated numbers. Every number in the report, slides or viva notes is read at build time from `results/*.json` produced by the pipeline. Text uses tokens such as `{{m:electricity.d1.test.lstm.mape|.1f}}`; the build fails on any unresolved token. Never type a result by hand.
2. No fabricated citations. Only cite entries in `report/references.yaml` whose `status` is `verified`. Verify by resolving the DOI (https://doi.org/...) or the Crossref API, or by opening the official URL, and confirm title, authors, venue, year and pages match. If something cannot be verified, ask the user; do not guess.
3. No illustrations from the internet (official rule). Every figure is generated by this repository's code or is a screenshot of this project's own dashboard. Report figures are black and white (greyscale, distinguishable by line style, marker and hatch). Slide figures may use colour and are generated from the same code.
4. Time-series hygiene. Chronological train, validation and test splits; no shuffling across time; scalers and encoders fit on training data only; every lag used for a horizon of h steps is at least h steps old; test data is touched only for final evaluation.
5. Honest results. Always report the seasonal-naive baseline. If a deep learning model does not beat a simpler model, the report says so and discusses why. Never tune on the test set.
6. Synthetic or injected data is always labelled as such in file names, column names, figure captions and report text.
7. Consistency with the approved synopsis: same title, same six objectives, same problem framing.
8. Report formatting is done only through `report/docx_format.py`. Extend that module if something is missing; do not restyle paragraphs ad hoc.
9. Reproducibility. Global seed 42 (Python, NumPy, TensorFlow); pinned `requirements.txt`; `python -m wef.cli all` rebuilds every result, figure and export from raw data.
10. Phase gates. Work one phase at a time. At each gate, run the gate checks, update section 7 below, summarise what changed and what the numbers are, then stop and wait for the user to say "proceed".
11. No invented people, names or institutional facts (for example the Director's name, the plagiarism tool's name, a tariff rate). Insert `[[CONFIRM: what is needed]]`; the report builder highlights these in yellow and lists them. The final build must contain zero CONFIRM markers.
12. Raw data, model binaries over 50 MB, `.env` files and credentials are never committed. `data/` is git-ignored.

## 6. Commands

- Environment: Python 3.11 in `.venv` (on Windows: `.venv\Scripts\Activate.ps1`; the package is installed editable with `pip install -e . --no-deps`); Node.js 20 or newer for the deck; LibreOffice for PDF conversion (set `SOFFICE` if `soffice` is not on PATH; on Windows it is usually `C:\Program Files\LibreOffice\program\soffice.exe`).
- Pipeline: `python -m wef.cli all` (or the individual stages listed above)
- API: `flask --app api.app run --port 5000`
- Dashboard: `streamlit run dashboard/app.py` (reads `WEF_API_URL`, default `http://127.0.0.1:5000`)
- Tests: `pytest -q`
- Report: `python report/build_report.py` then `python report/build_report.py --check`
- Format self-test: `python report/docx_format.py --selftest`
- Deck: `python presentation/make_deck_json.py && node presentation/build_deck.js`

All commands must work on Windows (PowerShell) and Linux. Use `pathlib`, never hard-coded separators. Do not rely on `make`.
